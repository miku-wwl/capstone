MSE907 Assessment 3 中文答辩与录制提纲

开场先讲一次已提交却丢失回复的转账。客户端再次发同一意图时，需要同时问账本是否正确、效果是否恰好一次、能否确认原结果。

机制及方法
1. 为什么 OCC OFF 仍然安全？当前行相对算术、WHERE 谓词、锁和两侧同事务。竞争写提交后 PostgreSQL 重新检查 WHERE。T1 与 T3 表明合法更新和回滚规则在共同路径工作。W5 旧值覆盖只在独立诊断表。
2. 为什么数据库事务无法代替请求幂等？事务约束单笔写入，两个不同尝试仍可能分别提交。C/D 将作用域 keys、载荷指纹、财务结果及回执一起提交。回滚释放未提交 owner，确定性拒绝用 savepoint。
3. 为什么 2×2？A/B 比较无键时版本校验，C/D 比较有键时版本校验。分别估计两项主效应与交互，统一隔离级别、schema、业务谓词和初态。
4. 为什么独立审计？回执不等于持久证据。配对请求、确认、transfer、两条分录和最终各账户。重复扣款的总账仍可能守恒。
5. W2 与 W4 匹配了什么？种子、热点、分配的重复率、到达与窗口。W2 同键并发，W4 在已确认提交后中断真实 HTTP 响应并同键重发。校核分配、合格、触发和实际重发。T12 的 PostgreSQL 提交不确定模拟是应用层诊断。
6. 为什么不能只看 HTTP TPS？尝试可以重复。正确逻辑吞吐固定分母 60 秒，分子要求一个匹配效果和按时有效确认。成功 P95 之外须报失败、未知、迟到和重复。
7. 为什么区组级分析？同一轮共享资源，不是独立样本。每个区组有 16 单元，计算区组内的因子及场景差，再估计跨区组区间。
8. Pilot 如何决定 n？五个配对区组，80 轮，δ=参考 TPS 的 10%。看 t×s/√n 与真实预算，正式前冻结。Pilot SD=0.063465，δ=11.999333，正式 n=10。

正式 160 轮，独立账本不变量异常单元 0。确认数与实际效果单列。

讲 W1-low/high 的 OCC、键和交互图，再讲 P95 与重试/等待，说明外部发送率限制了可见吞吐。
RQ3 ΔI +0.041667 [+0.020450, +0.062883] 请求/s。半宽 0.021216，目标 11.999333，状态 confirmatory。
半宽达标是精度标准。区间是否支持有方向的差异需另读，不能将近零自动解释为两策略等价。
