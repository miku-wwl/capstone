MSE907 Assessment 3 中文答辩与录制提纲
并发与重试负载下金融交易系统的数据一致性与性能权衡评估

开场（第 1–4 页）
用一笔已提交但丢失回复的转账引入。问清三件事：账是否对、这项意图执行了几次、调用者能否拿到原结果。RQ1 查效果与回执，RQ2 查固定负载下的代价，RQ3 查两套投递场景的交互差。

方法与机制（第 5–10 页）
四组共享相对更新、足额谓词、固定锁序和一个 READ COMMITTED 事务。B/D 加版本校验，C/D 加持久键。W2 并发发送同键同载荷，W4 在数据库确认提交后中断真实 HTTP，再按规约重发。两场景匹配种子、热点、负载及重复分配。每个区组包括 16 个单元，运行顺序独立随机。
从输入、账户、转账、分录和回执复原每项意图。正确确认吞吐以 60 秒为分母，符合规则的唯一匹配效果及按时回执计入分子。P95 只描述正确确认样本，需并列报告重复、窗口错过和其他不利结局。

结果（第 11–15 页）
RQ1。160 轮无共同财务不变量违例。W2/W4 的 A/B 观测到 56,532 个重复意图，每项多一笔效果，C/D 本次观测为 0。账本守恒成立，每个意图执行几次仍需独立检查。
RQ2。W1 各组 119.987–119.995 正确确认请求/秒，容量未发出 0。W1-low 的 OCC／键 P95 增量为 1.139／2.505 ms，W1-high 为 4.149／2.385 ms。B/D 冲突从 372 增至 5,681 次，约占事务尝试的 0.258% 和 3.796%。说明当前负载、成功样本选择，以及高竞争重试的实际代价。
RQ3。W2 的 (B−A,D−C)=(+25,−3)，W4=(+2,−1)。场景交互为 −28/600 和 −3/600，净差 +25/600。配对均值 +0.041667 请求/秒，95% CI [+0.020450, +0.062883]，折合每 60 秒 +2.5（+1.23 至 +3.77）个确认，约为输入率的 0.0347%。半宽 0.021216 小于预设 δ=11.999333，分类为 Confirmatory。绝对工程幅度很小。

工程选择、伦理与边界（第 16–18 页）
共享 SQL 保障所测的单笔事务契约。业务依赖先前状态时评估版本校验。在结果不明而可重试时，评估作用域持久键、载荷绑定和可恢复完成记录，检验保留期限并提供具权限的低带宽查询。实测是合成轨迹的重复效果，真实损失和网络状况未测。学生确认本地合成研究无需伦理审批，行政筛查由学生核对。讨论 Te Tiriti o Waitangi 和 Māori 数据主权时，说明未来需与相关主体议定授权、访问、再用和利益安排，当前数据不代表 iwi 或 hapū。

准备问答
1. 为什么选择 120 requests/s？冻结前用 Pilot 检查发送、两级热点与故障可行性。四个工况使用相同速率施加已知输入，以热借记概率（10%／80%）和投递历史区分工况。
2. 为什么没有测最大吞吐量？试验只设置一个输入率与并发上限。W1 接近 120 且无容量未发依然缺少饱和曲线。测最大可持续吞吐需要不同负载、足够的持续时间和排队／失败判据。
3. 该负载足够回答 RQ2 吗？可回答冻结负载的正确确认率、条件 P95 和事务成本。固定输入可观察 W1-high 的冲突与重试差。峰值容量、策略在其他负载的排序和生产表现需要新证据。
4. RQ3 为何统计非零而工程意义小？十个区组的 t 区间为正，绝对量是 +2.5 个确认/60 秒，约固定输入的 0.0347%。配对标准化效应 1.404879 的分母是较小的区组标准差。工程判断应立足于绝对量及成本。
5. 为什么 δ 与效应相差大？δ 是 Pilot 中 A/W1-high 平均正确确认吞吐的 10%，用于事前控制区间精度。它未衡量真实业务收益的最小差异。实测半宽 0.021216 表明估计精度达标。
6. 56,532 个重复是否意味着数据库事务失效？每笔各自守恒并可对账，共同不变量违例单元为 0。两个 HTTP 尝试仍能各提交一笔。持久完成记录使同键重试找回原回执，零观测重复只针对本次 C/D 暴露。
7. OCC 怎样影响 W2 的效果？事后匹配出 27 个 A 两笔、B 一笔的意图。B 的两次尝试都已发出并准入，未产生效果的一次经历四次版本冲突并耗尽重试（9 首发、18 重发）。反向 1 例为 A 错过测量窗，重复净差 26。W4 的 A/B 没有匹配重复差异。轨迹支持关联，目前缺少触发冲突的完整 SQL 时序，无法识别因果中介。C/D 的差也进入交互，主要是净窗口错过及一个 W2 操作失败。
8. 为什么 10 个区组足够满足精度？五个 Pilot 配对差的 SD 为 0.063465。冻结前预测十区组 95% 半宽约 0.0454，小于 11.999333 并符合预算。正式半宽按十个区组重新估计，达标范围是 RQ3 精度。
9. 为什么不能把超过 100 万个请求视为独立样本？同一轮请求共享热账户、调度器、数据库锁和缓存。先算同一区组的四臂差，再分析十个 W4−W2 差。请求级轨迹支持机制核对，推断单位仍为区组。
10. 相比 RIFL、Histrio、RTSFaaS 的贡献？RIFL 和 Histrio 提供对象或 actor 边界的持久执行先例，RTSFaaS 也有银行评估。本研究在同一安全 PostgreSQL 基线上交叉操纵版本校验与 HTTP 持久键，独立计量财务效果、确认和事务成本。不同运行时的性能数字只适用于各自边界。
11. 为什么 T12 无法证明真实数据库 COMMIT ACK 丢失时的恢复？T12 在应用层注入围绕真实数据库事务的提交不确定性，验证独立查询与安全响应。T7 实际断开提交后的 HTTP 回执链路。真实 PostgreSQL COMMIT ACK 通道丢失需要另设网络故障试验。
12. 为什么有硕士层级的研究深度？用文献界定工程空白，以共享安全基线、预注册配对设计、真实数据库、独立账本和区组级推断比较机制。用原始轨迹限定解释。结论可用于具体契约和测试范围的工程权衡。
