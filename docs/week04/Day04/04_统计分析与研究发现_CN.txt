Post-hoc Exploratory Mechanism Analysis
按区组、场景、工作负载种子及逻辑请求 ID 匹配，随后通过 Attempt ID 连接发送、HTTP、服务端准入、事务诊断和账本效果。以下是事后探索性分析。预注册估计及分类沿用冻结口径。

场景 | A/B/C/D 正确确认 | B−A（个） | D−C（个） | 交互（请求/秒）
W2 | 57,856 / 57,881 / 71,998 / 71,995 | +25 | −3 | −28/600
W4 | 57,855 / 57,857 / 71,997 / 71,996 | +2 | −1 | −3/600
两工况分别按每组十轮、累计 600 秒计。I_W4−I_W2 = +25/600 = +0.041667 请求/秒。
W2 的 B−A = +1 发出、+26 少重复、−2 多操作失败，D−C = −2 发出、−1 多操作失败。
W4 的 B−A = +4 发出、−2 多操作失败，D−C = −1 发出，对应多 1 次窗口错过。其他未正确确认类别对以上差分贡献为 0。

W2 有 27 个匹配意图在 A 产生两笔效果，在 B 产生一笔并正确确认。B 两次尝试均实际发送及准入，缺失效果的一次均为 HTTP 503、retryExhausted，四次事务尝试全部记录 versionConflict，未见锁超时或客户端传输失败。缺失的尝试中 9 个是首发、18 个是重发。反向 1 例为 A 错过发送时窗、B 产生两笔效果，故 A−B 的重复净差为 26。W4 的 A/B 各有 14,140 个重复意图，匹配后无重复方向不一致。
C/D 的正确确认差另行核对。W2 有 3 条 C 成功/D 窗口未发、1 条 C 成功/D 操作失败、1 条 C 窗口未发/D 成功，净 D−C=−3。W4 有 2 条 C 成功/D 窗口未发、1 条 C 窗口未发/D 成功，净差 −1。
RQ3_Mechanism_Analysis.json 列出 W2 的 37 条、W4 的 7 条匹配对照，覆盖有带符号交互贡献、A/B 重复分歧或 C/D 确认分歧的情况，含原始运行路径和哈希。27 条耗尽轨迹支持冲突与缺失效果的观测关联。归档只有每次 HTTP 尝试的事务累计计数和终态，缺少竞争写入的顺序及替换冲突机制后的反事实数据，无法识别经由冲突的因果效应。
