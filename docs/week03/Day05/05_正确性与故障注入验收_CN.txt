1. 实际验收

本机 .NET SDK 10.0.300、Kestrel 回环 HTTP 和 Docker PostgreSQL 17.7。Release build 0 错误、0 警告。58 个测试通过（7 个单元、51 个真实 PostgreSQL 集成测试），0 失败、0 跳过。金额、状态谓词、资金守恒、非负余额、借贷配对、原子性与客户端回执均有可复核断言。以下结论限于预定交错和合成环境。

编号 | 实际验证
T1 | A–D 各有两种屏障并发扣款。两笔 30 都能提交，两笔 60 仅一笔提交。两种场景期末借方 40，且对账通过。
T2 | 超额拒绝，余额、版本、转账和分录无变化。额外测试覆盖四组及 OCC 不误将可证余额不足归为冲突。
T3 | 第二账户不可用时，已发生的第一账户写入撤销。T11 和四组共同约束测试覆盖组合策略。
T4 | C/D 用 PostgreSQL 唯一键等待验证同键并发后只提交一次。A/B 的安全基线可提交两个独立财务效果。
T5 | 同键金额变化时，C/D 拒绝第二次操作，A/B 以正常请求再执行。实际结束状态均经独立账本核验。
T6 | C/D owner 已写入但在提交前注入回滚。等待者接管，最终只有等待者的效果和一条 completed 记录。
T7 | A–D 真实 Kestrel 连接上，确认 PostgreSQL COMMIT 后、HTTP 正文发送前中断。A/B 重发后各两次效果，C/D 各一次并返回原 transfer_id。
T8 | 控制竞争事务更新已读版本。ON 整笔回滚、读取新版本、重试后成功，OFF 使用当前行相对更新。
T9 | 四次可控版本冲突耗尽预算。主请求零效果，干扰请求的效果独立对平。
T10 | W5 只在隔离诊断表执行，两事务均读 100，覆盖后得到 85，正确相对更新应得 75。测试清理诊断表。
T11 | 四组均在第一侧写入后确定性拒绝。C/D 通过 savepoint 撤销财务写入并回放原拒绝，A/B 整笔回滚后可重新判断。四组无余额、版本或账本残项。
T12 | 在真实 PostgreSQL 提交前后受控注入应用层未知信号。A/B 保留 unknown。C/D 只有独立读取完成记录时才回放，否则 unknown。每个请求只尝试一次财务事务。真实 PostgreSQL 网络层 COMMIT ACK 丢失仍缺证据，且不属于主矩阵。
T13 | 四组使用真实账户行锁超时验证回滚，重新提交后只有新请求产生效果。持久键路径另验证锁等待超时后返回 KeyBusy，事务结束后可同键回放。

W3 通过真实 HTTP 返回 503，服务 trace 为 DeniedBeforeTransaction 且 TransactionAttempts=0。账本零转账、键表零记录。W0 是 W1-low 的参考别名。W3、W5 只做正确性诊断。

2. 全矩阵短窗口冒烟

本次 1 个工程区组，16 个单元，100 个合成账户，每窗计划 32 逻辑请求/秒，并发上限 16，预热/测量/drain 为 1/1/2 秒。每单元进入预热前及测量前从同种子恢复独立初态。实际 512 个逻辑请求均发出，16 个单元账本零审计违例，未发现截止点仍活跃的客户端任务。W1-low、高八个单元各确认 32 个逻辑请求。W2 和 W4 各组各触发五个事件，两场景在 A/B 各得到 27 个正确确认、5 个重复逻辑请求、37 个财务效果，在 C/D 各得到 32 个正确确认、0 个重复逻辑请求、32 个财务效果。各单元 unknown 为 0。结果只验证接线、触发与记账分类。

负载生成器保存逻辑 ID、尝试 ID、发送与确认相对时间、分配/合格/实际触发/重发、服务事务尝试、期初账户、期末账户与账本。verify 从 16 份原始 JSON 核验 SHA-256，重算全部摘要。本机原始证据目录为 _local_sources/engineering/day05-20261127T093053Z。Manifest SHA-256 为 3e85a6e2c9239315f2f1b06c7452d57822500019e41bb7ae92844b99a04acdd5。此次证据在 Day05 发布前生成，manifest 记录 Day04 基准与未提交工作树，保留运行器二进制 SHA-256。

3. 计量边界和后续条件

到测量期限后停止发起，drain 截止后取消未结束的客户端调用并关闭该阶段准入。等待服务退出及确认无本实验的数据库活动事务之后才审计或 reset。旧阶段令牌不得进入新阶段。无法确认清场时终止批次。P50/P95/P99 只取经账本验证的正确确认逻辑请求，空样本为 null。HTTP 尝试与内部事务重试另计。进程 CPU/RAM 是同一进程的 API 和生成器合值，数据库等待是离散采样，不能代替生产监控或 pilot 诊断。

候选配置为 experiments/workloads/candidate.json。已核对 80、160、224 个单元计划的完整区组和配对种子，计量窗口保持 30/60/30 秒。预备的 pilot 精度分析拒绝读取工程冒烟作为 pilot，正式研究尚无输入。CI 配置固定 .NET 与 PostgreSQL，包含锁定还原、编译、真实 PostgreSQL 测试和计划检查。GitHub Runner 的状态以发布后的实际工作流为准。
