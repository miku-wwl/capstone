MSE907 Capstone — 工程可行性、资源预算与 14 周计划
状态：规划估算，不是实施承诺或已验证结果；研究主题、技术栈、时间节点待导师确认。

1. 工程架构与边界

Client / deterministic load generator → ASP.NET Core API → transaction + idempotency layer → PostgreSQL accounts / transfers / ledger / idempotency_records → independent audit + metrics export。
故障注入点只模拟 API transaction begin 前 gate 和数据库 COMMIT 已确认后、HTTP body 写出前丢弃响应。注入器只连本地合成原型。所有账本审计离线执行；不得把观测埋点与业务结果混为同一来源。

2. 工作量核心矩阵

四条件：W1-low、W1-high、W2 concurrent same-key、W4 post-commit HTTP loss。每条件四组 A–D，各 10 个初始完整区组：4×4×10=160 次正式运行。每次 60 秒测量窗，纯正式测量 160 分钟=2 小时 40 分。pilot 初始五个区组/条件，共 80 次，纯测量 80 分钟=1小时20分；pilot 不进正式推断。
每次运行预算 180 秒：测量窗 60 秒、固定 drain 30 秒、预热 30 秒、数据重置/日志归档 30 秒、审计准备 30 秒。初始正式 160×180 秒=8 机器小时；pilot 80×180 秒=4 小时；20%正式复跑 reserve 为32次、1.6小时。另列环境/版本冻结 3 小时、最终批量 ledger reconciliation 与导出 2 小时、分析脚本执行 1 小时；初始 n=10 合计 19.6 小时，24 machine-hours 内留 4.4 小时余量。每增加 1 个共同正式区组，正式及向上取整复跑 reserve 约增 0.96 小时，因此在固定预算内最多 n=14（正式224次、reserve45次，合计约23.45小时）。Pilot 后如果精度要求超过14组，保留全部工况并使用不超过14个共同区组，RQ3按预先规则降为 exploratory；不得选择性删除不利工况。环境诊断可用余量须在 pilot 中确认；预算若仍不可行，必须在正式结果前暂停并与导师缩小范围。

5. 资源、伦理及失败缩减规则

一台本地隔离主机、一个 API 实例、一个 PostgreSQL 实例、合成数据；不需要云资源/外部付费。日志封顶 10 GB，轮次结束检查磁盘/PII。性能试验先确认 load generator 不成为瓶颈，固定 CPU governor / 电源与后台任务状态（若可控），记录温度或 throttling。伦理审查与合成数据的正式适用性须由 supervisor/institution 确认，不自行宣称豁免。

基础设施失效只按预定义整 block 重跑，保留失败记录。若精度目标超过 14 blocks、数据收集窗口不足或原型不能达到测试触发能力，则在未查看 confirmatory outcomes 前缩小声明、转 exploratory 或暂停，不选择性删掉“不好看”的条件。适用范围只到本地单库原型，不外推为银行生产 benchmark。
